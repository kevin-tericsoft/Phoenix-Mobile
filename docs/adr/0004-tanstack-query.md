# ADR 0004 — TanStack Query + generated OpenAPI client

**Status:** accepted · **Date:** 2026-06-24

## Context
The old app fetches data imperatively: `axios` calls inside screens and a partial
`redux-saga` layer (only `auth.saga` exists), with RxJS subjects shuttling the auth token
around. Loading/error/caching are hand-rolled per screen. The new backend (FastAPI) publishes
an OpenAPI spec.

## Decision
- **Server state → TanStack Query** (`useQuery`/`useMutation`).
- **Typed HTTP client → `openapi-fetch`** over types generated by **`openapi-typescript`**
  from the live spec (`src/api/schema.d.ts`, regenerated via `npm run gen:api`).
- **Client state** (am-I-logged-in) stays in a small React context (ADR 0005); Redux is
  dropped entirely.

## Why
- **Caching/loading/error/refetch for free.** Replaces the saga boilerplate (actions,
  reducers, watchers) with a one-line hook. You already know this pattern from React Query
  on the web — it transfers verbatim.
- **Types from the contract, not by hand.** The client is type-checked against the backend's
  own schema; a contract change becomes a TypeScript error after `gen:api`. No DTO drift.
- **Right-sized.** Redux + saga is heavyweight for what is mostly request/response. Query
  fits the actual shape of the app.

## Alternatives considered
- **Port Redux + saga, repoint endpoints.** Rejected: carries a heavy pattern and lots of
  boilerplate for little benefit.
- **Heavyweight client generator (e.g. orval/openapi-generator).** Rejected: `openapi-fetch`
  is tiny (no generated method-per-endpoint), runtime-light, and pairs cleanly with Query.

## Consequences
- A `scripts/gen-api.mjs` step pre-processes the spec (strips redundant `Authorization`
  header params; see ADR 0005 / BACKEND-GAP) before generating types.
- Feature data lives in `features/<x>/queries.ts` as typed hooks — the seam every screen uses.
- Backend changes require re-running `gen:api`; CI should fail if the committed schema is stale.
